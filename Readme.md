# Amazon Clone

A full-stack e-commerce mobile application built with Expo, React Native, and a TypeScript REST API. The app includes authentication, browsing, search, cart, wishlist, address management, checkout, and order history flows backed by MongoDB.

## Overview

This project is split into two applications:

- A mobile storefront built with Expo Router and React Native.
- A Node.js API built with Express, TypeScript, and MongoDB.

The frontend talks to the API for user accounts, addresses, and orders, and also fetches catalog data from FakeStore for product browsing.

## Tech Stack

### Mobile App

- Expo SDK 51
- React Native 0.74
- Expo Router for file-based navigation
- TypeScript
- NativeWind + Tailwind CSS for styling
- TanStack Query for server state
- Zustand for local state management
- Axios for HTTP requests
- AsyncStorage for persisted auth state
- react-hook-form and Zod for form handling and validation
- Lottie for animated UI states
- Expo vector icons and Expo modules for native integration

### API

- Node.js
- Express 4
- TypeScript
- MongoDB with Mongoose
- JWT-based authentication
- bcryptjs for password hashing
- Zod for request validation
- Helmet and express-rate-limit for security hardening
- CORS and Morgan for HTTP handling and logging
- Nodemailer for transactional email
- tsx for development-time execution

### External Services

- MongoDB Atlas or any MongoDB deployment
- FakeStore API for product catalog data
- Email provider for account verification and notifications

## Features

- User registration and login with JWT authentication
- Auth persistence with automatic redirect handling
- Email verification flow for new users
- Home feed with banners, product cards, and category browsing
- Search experience backed by React Query and debounced input
- Wishlist with persisted local state
- Cart with quantity updates and subtotal handling
- Address book for checkout and order placement
- Multi-step checkout experience
- Order creation and order detail views
- Empty states and skeleton loaders for loading and no-data states
- API security headers, rate limiting, and input validation

## API Contract

Base path: `/api/v1`

| Method | Path | Purpose |
|---|---|---|
| POST | `/users/register` | Create a new user |
| POST | `/users/login` | Authenticate and return a JWT |
| GET | `/users/verify/:token` | Verify a newly registered user |
| GET | `/user/profile/:userId` | Fetch profile details |
| POST | `/address/add` | Add a delivery address |
| GET | `/address/:userId` | List saved addresses |
| DELETE | `/address/:userId/:addressId` | Remove an address |
| POST | `/order/add` | Create an order |
| GET | `/order/:userId` | List orders for a user |
| GET | `/order/detail/:id` | Fetch order details |
| GET | `/health` | Health check |

## Environment Variables

### API

Create a file such as `api/.env` with values similar to the following:

```bash
PORT=8000
IP_ADDRESS=0.0.0.0
MONGODB_URI=mongodb+srv://<user>:<pass>@<cluster>/amazon-clone
JWT_SECRET=replace-with-a-long-random-string
EMAIL_USER=your-email@example.com
EMAIL_PASS=your-email-app-password
```

### Mobile App

Update `src/lib/api.ts` so `API_URL` points to your backend:

```ts
export const API_URL = 'http://<your-local-ip>:8000/api/v1';
```

When testing on a physical device, the API host must be reachable from the device on the same network.

## Architecture Notes

- The root layout hydrates auth and wishlist state before rendering the app shell.
- React Query is used for caching and request lifecycles across product, order, and profile screens.
- The API client automatically attaches the JWT from AsyncStorage and clears it if the backend returns `401`.
- The API exposes a separate Axios client for FakeStore so catalog requests stay isolated from authenticated calls.
- Security-sensitive routes are protected through middleware on the Express side.

## Production Considerations

- Use a real secret manager for `JWT_SECRET` and email credentials.
- Point the mobile app at a stable API domain instead of a local network address.
- Configure MongoDB access control and network restrictions for production.
- Enable HTTPS for the backend and any deployed mobile-facing API host.

## Notes

- The repository currently contains both the mobile app and the backend API in one workspace.
- The app is designed to run with a local development backend, but it can be wired to any compatible deployment by changing the API base URL.
